# 张力与兑现（Tension & Payoff）

本手册供策划编辑编阶段章拍、创意编辑设计跨卷承诺、总编辑签发与复核。方法依据是
[Sanderson 的 Promise–Progress–Payoff 讲座](https://www.brandonsanderson.com/blogs/blog/brandon-sandersons-2025-guide-to-plot-lecture-2)、
[Sanderson 的长期伏笔答疑](https://faq.brandonsanderson.com/knowledge-base/how-do-you-use-foreshadowing/)
与 [Writing Excuses 的长连载伏笔讨论](https://writingexcuses.com/18-34-seventeen-years-of-foreshadowing/)：
开篇形成期待，过程中让局势有可感知的变化；回收时回看成立，同时让当下剧情发生变化。
这些是审稿方法，不是固定章距公式。不得把参考作品的设定、人物、数值或原句带入项目。

## 1. 三种尺度

| 尺度 | 读者当下看到什么 | 记录与处置 |
|---|---|---|
| 场内张力 | 人物有目标，遭遇具体阻力，作出选择；结果带来代价或新反应 | 写进 `beats[].text`，结果才写 `effects`。即使是休整戏，也要改变关系、信息或下一步行动 |
| 近期显性承诺 | 人物公开约定、眼前疑问或已经被强调的期待 | 用 `effects.hooks` 同 id 埋收，`due` 是预计兑现章；跨度约 15 章是**软建议**，逾期用 `hooks audit` 对账 |
| 跨卷低调伏笔 | 一个已在当场起作用的事实、物件、误判或关系，日后会获得更深意义 | 在 `book_outline.long_term_commitments` 登记书级承诺；正文的首次埋种与中途变化用**同 id** hook 留证，最终 `paid` |

显眼的主谜、公开誓言或迫在眉睫的危机属于读者正在等待的**显性承诺**。不能只把 `due`
写成几百章后，就让它长期没有答案；每卷应给出可验证的局部解决，再由新事实自然改变问题。
长线伏笔可以沉潜：读者首次见它时，先关心它在当前戏里造成的具体后果，不必被旁白宣布为终局谜底。

## 2. 起伏来自因果变化

编一场戏时检查「**目标 → 阻力 → 选择 → 结果 → 代价/反应**」。一章不必每场都复制这个形状，
但不能只有谈论风险而无人物行动。跨章起伏则看阶段 `entry_state → exit_state`：
角色可用的信息、关系、资源、时限与风险至少有一项真实改变。成功可以带来新代价，失败可以
获得可用信息，喘息可以让人物重新选择；转折要由已知人物动机和世界规则推动。

策划编辑先定本阶段的核心问题与阶段高潮，再交错安排施压、试探、误判、局部结算与余波。
铺垫章可以不兑现，但须改变局势；兑现章须收回一个**已经建立**的期待，并留下因果后果。
同样的“受辱—反击—围观惊叹”或每隔固定章数一次反转，都不能代替情节推进。

| 旧量控提示 | 用法 |
|---|---|
| 连续无兑现约 3 章、小兑现约每 3–5 章 | 只在批次审稿时提醒检查读者是否看到进展；不按计数硬插一场爽点 |
| 每卷至少一次大兑现 | 优先结算本卷 `goal`，确认人物得失与下一卷入口态 |
| 同章新埋显性期待约 2 条、近期期待约 15 章内处理 | 防止注意力分散与到期承诺蒸发；跨卷低调伏笔另按下节记录 |

## 3. 长线承诺的埋种、显形与回收

书级记录放在 `plan.book_outline.long_term_commitments[]`。开书输入基础必需
`promise`、`planted_volume`、`resolved_volume`；建议再给 `id`、`arc_ref`、`seed_use`、
`final_condition`，可选 `description`。未给 `id` 时开书生成稳定 id；落盘后的 id 必须与账本
hook 共用。`arc_ref` 指向现有 `event_spine` 线路，`seed_use` 写首次埋种**在当场已经做了什么**，
`final_condition` 写能由正文和账本验证的结算状态。缺这些增强项仍可开书，但阶段定向显形
和最终复核缺少明确依据。`resolved_volume` 是书级目标，不要求提前写完几百章细纲。

1. **埋种**：早期场景先让线索解决局部问题、造成损失或改变人物判断；在该场 `effects.hooks`
   用同 id、`status:"open"` 登记。可以等收束阶段的具体章数确定后再填 `due`；填了时它表示
   **最终承诺的到期章**，不是下一次显形的倒计时。不要把长线埋种伪装成“明日揭晓”。
2. **定向显形**：扩纲 brief 按相关性给 `long_term_commitments` 和相关账本 hook；策划按本阶段
   的 `arc_ref`、眼前冲突与人物处境挑选有用的线索。在某章 `effects.hooks` 复用同 id，
   保持 `status:"open"`，更新 `text` 为**新理解或新因果**。正文必须演出它带来的决定、代价或
   关系变化；事实编辑在 `state_delta.hooks` 附本章逐字 `quote`。仅重复出现旧物或提醒读者
   “还有这个谜”，不算显形。没有自然场景就暂不出现，不按每 N 章打卡。
3. **兑现**：在 `resolved_volume` 附近的当前冲突中，让既有线索改变人物选择或胜负，
   达成已填的 `final_condition`，按同 id 把 `status` 置 `paid` 并附正文证据。
   `hooks close` 用于有理由地放弃/结案，
   不能冒充正文兑现；改约须保留裁决和新的排期。

卷级复核沿同 id 回看事件链、原始埋种和中途显形，只定向读取相关章节。发现旧事实与拟定答案
冲突时，使用已发生事实搭桥、调整未来结算或明确放弃强解；不得倒改既有事件来制造“早有伏笔”。
人物当时相信的**表象或解释**可以被新证据修正；已发生的行动、物件状态、逐字引文与世界
客观规则不能因此改写。可选的 `book_outline.long_arc_question` 只保存编辑层的谜题、人物表象
与揭示阶梯，供阶段策划使用，不进入逐章写者 pack，更不能把 `surface_illusion` 当世界硬规则。

## 4. 回收审稿四问

1. **回看公平吗？** 初次线索及中途变化在原场景里真实存在，读者回看能理解这个结果；
   正文没有故意替作者向读者隐瞒人物本应知道的关键事实。
2. **当下需要吗？** 回收由当前问题逼出，人物必须用它作选择并承担代价，而非停下剧情讲旧案。
3. **解决了什么？** 它实质解决或改变当前冲突，同时结算原先的书级承诺。
4. **历史可追吗？** 已填的 `seed_use`、同 id hook 的 `open → open → paid`、逐字 `quote`
   与终局状态能对上；
   若对不上，先修后续方案或留痕关闭，不伪造旧证据。

机器负责追踪 id、到期、证据与按需召回；自然程度和惊喜是否成立由总编辑按上述问题审稿。
